# 공통 프레임워크와 샘플의 경계

[← 개요](../README.md)

Direct3D 응용에는 윈도우 생성, 메시지 처리, 장치 설정, 프레임 반복, 리소스 해제 같은 공통 작업이 필요합니다. 원본은 이를 KCoreLib에 두고 지형·FBX 등의 샘플에서 활용합니다.

| 구성 | 주요 책임 |
|---|---|
| KWindow | 윈도우와 메시지 처리 기반 |
| KDevice | Direct3D 장치·컨텍스트·스왑체인, 렌더 타깃·깊이 버퍼 |
| KCore | 초기화·프레임 갱신·렌더·종료 순서 |
| 입력·타이머·카메라 | 사용자 입력과 시간, View·Projection 변환 |
| 리소스 매니저 | 셰이더·텍스처 등 로드된 항목의 검색과 재사용 |
| 3D 객체 | 정점·인덱스·변환·색상 등 그리기에 필요한 상태 |
| BaseSample1 | 지형 메시와 마우스 피킹·편집 |
| FBXLoader | 외부 모델 구조를 읽고 객체 및 변환 트랙으로 구성 |

## 프레임워크와 응용의 분리

KCore는 입력·카메라·시간 등 공통 갱신과 화면 초기화·출력을 처리합니다. 각 샘플은 자신의 초기화·갱신·렌더·해제 작업을 제공합니다. 공통 실행 흐름을 유지하면서 응용 내용을 바꾸는 구조입니다.

## CPU 상태와 GPU 상태의 경계

정점 배열이나 객체의 행렬을 CPU에서 바꿨다고 GPU가 자동으로 새 값을 사용하는 것은 아닙니다. 버퍼 갱신과 셰이더에 전달하는 상태가 함께 맞아야 합니다. 지형 편집과 행렬·색상 갱신에서 이 경계를 확인할 수 있습니다.

## 외부 기술의 역할

Direct3D는 장치와 그래픽 파이프라인 API, FBX SDK는 외부 파일의 장면·메시·애니메이션 해석, Dear ImGui는 조작 화면을 제공합니다. 프로젝트의 설명 대상은 이 기능들을 프레임워크와 샘플의 동작에 연결한 구조입니다. 원본에 포함된 외부 라이브러리 파일의 양을 자체 구현 규모로 계산하지 않습니다.

## 유지보수 관점

전역 접근과 싱글턴 매니저는 샘플에서 쉽게 사용할 수 있지만, 초기화 순서와 해제 순서에 대한 결합을 만듭니다. 현재 구조를 학습 사례로 설명하며 다중 장치·멀티스레드·비동기 리소스 파이프라인까지 지원한다고 확장해 해석하지 않습니다.
